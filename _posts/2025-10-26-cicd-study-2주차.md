CloudNet@ CICD Study 1기 정리

Helm은 템플릿 기반으로 값을 받아 배포하는 도구이며,

관련 매니페스트 파일을 하나의 논리적 배포 단위인 차트(Chart)로 패키징.

pacman이라는 이름으로 Helm Chart 디렉터리 레이아웃을 생성.

Chart.yaml, templates/, values.yaml을 포함.

Chart.yaml은 차트의 이름, 버전, 설명과 같은 메타데이터를 담는 파일입니다.

|  |  |  |
| --- | --- | --- |
| version | 차트 버전입니다. 차트의 정의(템플릿 등)가 바뀌면 업데이트합니다. |  |
| appVersion | 애플리케이션 버전입니다. 실제 애플리케이션 코드/이미지가 변경될 때 갱신합니다. |  |

Chart.yaml

```yaml
apiVersion: v2
name: pacman
description: A Helm chart for Pacman
type: application
version: 0.1.0 # 차트 버전
appVersion: "1.0.0" # 애플리케이션 버전
```

### templates/deployment.yaml

{% raw %}Deployment 리소스를 정의하며, Go 템플릿 문법({{ }})을 사용하여 동적인 값을 참조합니다.{% endraw %}

{% raw %}* {{ .Chart.Name}}: Chart.yaml의 name 값을 가져옵니다.{% endraw %}
{% raw %}* {{ .Values.replicaCount}}: values.yaml에 정의된 복제본 수를 가져옵니다.{% endraw %}
{% raw %}* {{- toYaml .Values.securityContext \| nindent 14 }}: securityContext의 값을 YAML 객체로 주입하며, nindent 14 함수를 사용하여 14칸 들여쓰기를 자동으로 처리{% endraw %}
* template/deployment

{% raw %}
```bash
cat << EOF > templates/deployment.yaml apiVersion: apps/v1 kind: Deployment metadata: name: {{ .Chart.Name}} labels: app.kubernetes.io/name: {{ .Chart.Name}} {{- if .Chart.AppVersion }} app.kubernetes.io/version: {{ .Chart.AppVersion | quote }} {{- end }} spec: replicas: {{ .Values.replicaCount }} selector: matchLabels: app.kubernetes.io/name: {{ .Chart.Name}} template: metadata: labels: app.kubernetes.io/name: {{ .Chart.Name}} spec: containers: - image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion}}" imagePullPolicy: {{ .Values.image.pullPolicy }} securityContext: {{- toYaml .Values.securityContext | nindent 14 }} name: {{ .Chart.Name}} ports: - containerPort: {{ .Values.image.containerPort }} name: http protocol: TCP EOF
```
{% endraw %}

### templates/service.yaml

Service 리소스를 정의하며, Deployment와 마찬가지로 템플릿을 사용하여 값을 가져옵니다

{% raw %}
```stylus
cat << EOF > templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app.kubernetes.io/name: {{ .Chart.Name }}
  name: {{ .Chart.Name }}
spec:
  ports:
  - name: http
    port: {{ .Values.image.containerPort }}
    targetPort: {{ .Values.image.containerPort }}
  selector:
    app.kubernetes.io/name: {{ .Chart.Name }}
EOF
```
{% endraw %}

values.yaml 작성 (기본값 정의)

{% raw %}values.yaml은 차트의 기본 구성 값을 정의하며, 템플릿 파일에서 {{ .Values.&lt;key&gt; }} 형태로 참조됩니다.{% endraw %}

* securityContext: {}로 빈 객체를 설정하는 이유는 Deployment 템플릿에서 toYaml 함수를 사용했기 때문입니다. 빈 객체라도 YAML 객체 형태여야 합니다

```dts
cat << EOF > values.yaml
image: # image 절 정의
  repository: quay.io/gitops-cookbook/pacman-kikd
  tag: "1.0.0"
  pullPolicy: Always
  containerPort: 8080

replicaCount: 1
securityContext: {} # securityContext 속성의 값을 비운다 (YAML 객체)
EOF
```

쿠버네티스에 실제로 배포되기 전에 Helm이 YAML 파일을 어떻게 생성하는지 helm template 명령어로 미리 확인할 수 있습니다.

1. 기본값으로 렌더링 확인
2. 출력 결과에서 replicaCount는 1, image 태그는 "1.0.0"으로 설정된 것을 볼 수 있습니다.
3. --set 옵션을 사용하여 기본값 재정의 테스트**:** CLI에서 --set 파라미터를 사용하면 values.yaml의 기본값을 덮어쓸 수 있습니다.
4. 이 명령을 실행하면 렌더링 결과 YAML에서 replicas: 값이 3으로 변경된 것을 확인할 수 있습니다.

### 템플릿 코드 재사용 (Templates Reusing)

{% raw %}Deployment의 selector와 template.metadata.labels, 그리고 Service의 selector와 같이 여러 매니페스트에 중복되는 코드 (예: app.kubernetes.io/name: {{ .Chart.Name}})를 _helpers.tpl 파일에 정의된 단일 블록으로 대체하여 코드 중복을 제거하고 유지보수성을 향상시키는 것{% endraw %}

define 액션을 사용하여 재사용 가능한 템플릿 코드 블록을 정의합니다.

{% raw %}
```crystal
cat << EOF > templates/_helpers.tpl
{{- define "pacman.selectorLabels" -}} # stetement 이름 정의
app.kubernetes.io/name: {{ .Chart.Name}} # 해당 statement가 하는 일을 정의
{{- end }}
EOF
```
{% endraw %}

{% raw %}* {{- define "pacman.selectorLabels" -}}: pacman.selectorLabels라는 이름으로 이 코드 블록을 정의합니다.{% endraw %}
{% raw %}* [app.kubernetes.io/name:](http://app.kubernetes.io/name:) {{ .Chart.Name}}: 이 레이블 정의 자체가 재사용될 코드 블록의 내용이 됩니다.{% endraw %}

### 기존 템플릿 파일 수정 (include 및 nindent 사용)

기존 deployment.yaml과 service.yaml에서 중복되던 레이블 정의를 include 함수를 통해 _helpers.tpl에 정의된 블록을 호출하도록 수정합니다. 이때 들여쓰기(Whitespace)가 깨지지 않도록 nindent 함수를 반드시 사용해야 합니다.

* include "pacman.selectorLabels" **.**: _helpers.tpl에 정의된 pacman.selectorLabels 템플릿을 호출합니다. 이때 . (점)은 현재 컨텍스트(차트 정보, 값 등)를 템플릿 블록으로 전달하는 역할을 합니다.
* \| nindent X: 호출 결과를 파이프(\|)로 받아서 X칸 만큼 들여쓰기를 적용합니다. YAML 구조가 깨지지 않게 하는 핵심 기능입니다

deployment.yaml 내부에서 matchLabels는 6칸 들여쓰기가 필요하고, template.metadata.labels는 8칸 들여쓰기가 필요합니다

{% raw %}
```dts
## templates/deployment.yaml 수정 부분

## selector: matchLabels 부분 (6칸 들여쓰기)
selector:
  matchLabels:
  {{- include "pacman.selectorLabels" . | nindent 6 }} # 6칸 들여쓰기하여 주입 [6]

## template: metadata: labels 부분 (8칸 들여쓰기)
template:
  metadata:
    labels:
    {{- include "pacman.selectorLabels" . | nindent 8 }} # 8칸 들여쓰기하여 주입 [6]
```
{% endraw %}

service.yaml 수정 예시

service.yaml 내부에서 selector 필드는 6칸 들여쓰기가 필요합니다.

{% raw %}
```dts
## templates/service.yaml 수정 부분

spec:
  ports:
    # ... (포트 정의 생략)
  selector:
  {{- include "pacman.selectorLabels" . | nindent 6 }} # 6칸 들여쓰기하여 주입 [6]
```
{% endraw %}

만약 이제 공통 레이블에 애플리케이션 버전(app.kubernetes.io/version)을 추가하고 싶다면, deployment.yaml과 service.yaml 세 곳을 모두 수정하는 대신,  _helpers.tpl 파일만 수정하면 됩니다.

1. _helpers.tpl 수정:
2. 렌더링 확인
3. helm template .를 다시 실행하면, deployment.yaml과 service.yaml의 모든 selector 및 labels 블록에 app.kubernetes.io/version: "1.0.0" (Chart.yaml의 appVersion 값)이 자동으로 추가되어 표시됩니다

## **의존성 차트 배포**

Helm은 Chart.yaml 파일의 dependencies 섹션을 사용하여 하위 차트(sub-chart)를 정의하고, 하나의 helm install 명령으로 메인 애플리케이션과 의존성 서비스를 함께 배포할 수 있습니다.

Music 서비스 템플릿 작성 및 PostgreSQL 환경 변수 정의

Music 서비스 Deployment 템플릿은 PostgreSQL 접속 정보(JDBC URL, 사용자 이름, 암호)를 환경 변수(env)로 설정해야 합니다. 비밀번호는 쿠버네티스 Secret에서 참조하도록 구성됩니다.

* QUARKUS_DATASOURCE_PASSWORD 환경 변수는 valueFrom.secretKeyRef를 통해 PostgreSQL 차트가 생성할 Secret에서 값을 가져옵니다.

ConfigMap 변경 시 자동 롤링 업데이트 트리거

ConfigMap이나 Secret의 내용이 변경되어도 Deployment에 연결된 Pod는 자동으로 재시작되지 않는 쿠버네티스의 문제점을 해결하는 실습입니다. Helm은 sha256sum 함수를 사용하여 이 문제를 해결합니다.

Deployment 템플릿 수정 (Annotation 추가)

templates/deployment.yaml 파일의 Pod 템플릿 메타데이터(metadata.annotations)에 configmap.yaml 파일 내용의 SHA-256 해시 값을 주입합니다.

{% raw %}
```yaml
## templates/deployment.yaml 내 template.metadata 섹션

  template:
    metadata:
      labels:
        app.kubernetes.io/name: {{ .Chart.Name}}
      annotations:
        # configmap.yaml 렌더링 결과의 체크섬을 주입 [45-49]
        checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
    spec:
      # ... (컨테이너 정의 계속)
```
{% endraw %}

* include (print $.Template.BasePath "/configmap.yaml") .: ConfigMap 템플릿 파일이 최종적으로 렌더링될 내용을 읽어옵니다.
* \| sha256sum: 읽어온 내용 전체의 SHA-256 해시를 계산합니다.
* ConfigMap의 내용(values에서 주입된 값)이 변경되면 해시 값이 달라지고, 이는 Deployment의 Pod 정의를 변경하는 것으로 간주되어 자동으로 롤링 업데이트가 트리거됩니다.

### ConfigMap 파일 준비

Deployment가 환경 변수 형태로 참조할 값을 담을 ConfigMap 템플릿을 작성합니다.

Deployment 생성**:** greetings Deployment와 Pod가 생성되며, 이때 Pod의 어노테이션(annotations)에는 templates/configmap.yaml 파일 내용 전체를 기반으로 계산된 최초 SHA-256 체크섬 값이 기록됩니다

애플리케이션에 적용될 설정 값(ConfigMap 내용)을 변경합니다. 이때 ConfigMap YAML 파일 자체를 수정하는 대신, 템플릿에 주입되는 원본 데이터인 values.yaml을 수정합니다.

수정 내용 예시 (values.yaml):

values.yaml 파일을 열어 configmap.greeting 또는 이와 유사한 키의 값을 변경합니다.

* 예시: greeting: Hello를 greeting: Hello 2으로 수정

수정된 values.yaml 파일을 포함하여 Helm Release를 업그레이드합니다.

명령어**:**

```bash
helm upgrade greetings .
Release "greetings" has been upgraded. Happy Helming!
NAME: greetings
```

업그레이드 시 동작 원리:

1. Helm은 수정된 values.yaml을 로드하고 모든 템플릿을 다시 렌더링합니다.
2. configmap.yaml이 렌더링될 때, 변경된 값(예: "Alohas again")이 포함되어 ConfigMap의 내용 자체가 변경됩니다.
{% raw %}3. deployment.yaml이 렌더링될 때, checksum/config 어노테이션 로직({{ include ... \| sha256sum }})이 변경된 ConfigMap의 내용을 기반으로 새로운 SHA-256 해시 값을 계산합니다.{% endraw %}
4. Helm은 이 새로운 해시 값을 가진 Deployment Manifest를 쿠버네티스 API 서버에 전송합니다.

### 롤링 업데이트 확인

Helm이 새로운 해시 값을 Deployment의 Pod 템플릿에 성공적으로 주입했기 때문에, 쿠버네티스는 Pod 정의가 변경되었다고 인식하고 자동으로 롤링 업데이트(Rolling Update)를 시작해야 합니다.

4.1. Pod 목록 모니터링 (롤링 업데이트 확인)

helm upgrade 실행 직후 Pod 상태를 실시간으로 모니터링하여 새로운 Pod가 생성되는지 확인합니다.

```routeros
kubectl get pod -w
```

* 새 ReplicaSet 생성**:** Deployment가 새로운 ReplicaSet을 생성하고, 새 ConfigMap 내용을 반영한 Pod를 만들기 시작합니다.
* Pod 교체**:** greetings-xxxxx 형태의 새로운 Pod가 Running 상태로 전환되고, 이전 버전의 Pod는 점진적으로 Terminating 상태로 종료되는 롤링 업데이트 과정이 관찰되어야 합니다.

### Deployment Annotation 값 변경 확인

롤링 업데이트가 트리거된 원인이 실제로 checksum/config 어노테이션의 변경 때문인지 Deployment를 확인하여 검증합니다.

```bash
kubectl describe deploy greetings | grep checksum/config
```

* 업그레이드 전 확인했던 최초 체크섬 값과 달리, Deployment의 Pod 템플릿 메타데이터에 기록된 checksum/config 어노테이션의 값이 새로운 해시 값으로 변경되었음을 확인할 수 있습니다

## **Tekton 소개**

 쿠버네티스 기반 오픈 소스 클라우드 네이티브 CI/CD 시스템입니다.

CI/CD 파이프라인을 쿠버네티스의 CRD(Custom Resource Definition)로 정의하고 실행합니다.

* Task**:** 특정 기능(예: 컨테이너 이미지 빌드)을 수행하는 재사용 가능한 일련의 단계(Step)로 정의됩니다. Task는 쿠버네티스 Pod로 실행되며, 각 Step은 컨테이너에 대응됩니다.
* Pipeline**:** 앱을 빌드하거나 배포하는 데 필요한 Task들의 목록입니다.
* TaskRun/PipelineRun: Task 또는 Pipeline의 실행 인스턴스 및 그 결과입니다.
* Workspace: Task에 속한 Step 간에 파일 시스템을 공유하는 메커니즘으로, PVC, ConfigMap, 또는 emptyDir 볼륨을 사용합니다

Tekton 네임스페이스 확인**:** kubectl get ns \| grep tekton

cli 설치

brew install tektoncd-cli

hello-task.yaml

```dts
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: hello # Task의 이름
spec:
  steps:
    - name: echo # step 이름 [2]
      image: alpine # step 수행 컨테이너 이미지 [1, 2]
      script: | # 실행할 스크립트 [1]
        #!/bin/sh
        echo "Hello World"
```
```ada
kubectl apply -f hello-task.yaml
```

