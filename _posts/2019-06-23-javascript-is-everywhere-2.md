마지막 세션은 격변하는 프론트엔드 환경에서 빠르게 새로운 것 익히기 / 조현영

발표를 들었습니다. JS 개발을 하게되면 어떻게든 들리게 된다는 zerocho님의 블로그.

오늘 세션중 꼭 듣고 싶었던 세션중에 하나였습니다.

최근의 프론트엔드는 정말 다양하고 급변하고 있습니다.

제로초님은 어떻게 이러한 변화에 적응을 하는가

먼저,

**어느정도면 할 줄 아는가?**라는 질문에

원리 이해가 제일 먼저 필요하다고 말씀하셨습니다.

세부적인 작동 코드를 모두 기억하지 못하더라도

추상적 이해를 하게 되었다면

나중에 다시보더라도 다시 적응하는데 오래걸리지 않는다고 합니다.

**왜 새로운 것을 해보는가?**

이유가 없으면 안배워도됨

개인적이유 : 호기심, 성장욕구

사회적이유: 주변의 감시&선언(언제까지 ~~를 학습하겠다), 회사가 시켜서...

**어떻게 하면 효과적으로?**

동기를 부여한다. 스스로에게 보상, 환경만들기 또는 환경에 쳐하기

올바르게 학습하는 방법은 무엇일까?

이상한 방법으로 학습을 하게되면 효과가 적습니다.

스스로 터득하는 방법을 익해야하고, 좋은 스승님을 만나는게 좋습니다.

**안좋은 방법은?**

1.공식문서를 안보고, 강의에 의존하는것.

개발하고 싶은것이 있고 어떻게 할것인지 공식문서에서 적용할 생각을 해보자!

[https://kr.vuejs.org/v2/guide/index.html](https://kr.vuejs.org/v2/guide/index.html)

2\. API 만 달달외움.

원리를 모르면 응용하기 어려움.

3\. 튜토리얼만하고 빠지기.

=&gt; 다양하게 활용을 해보자

4\. 에러를 해결못하는것. 주변에 의존하기.

=&gt; 에러를 구글링해보기, 에러 메시지를 읽으려고 노력하기

5\. 사소한것에 집착. 큰 그림, 원리를 익히려고 하자.

예를 들어 이번달에 리액트를 해보기로 마음먹었다면

1\) 공식문서를 보기, 2) 튜토리얼을 따라해보기 3) 자신만의 프로젝트 만들기.

가능하다면 실제 서비스 수준까지 개발해보는것이 중요하다고 하셨습니다.

**프로젝트를 무엇을 시작할지 모르겠다면 블로그 개발을 추천**

커뮤니티에 홍보를 하면 실사용자를 모을 수 있다.

풀스택 공부를 해볼 수 있다.

다양하게 블로그를 활용할 수 있다.

**코드 피드백의 중요성**

스터디를 하는 방법이 있지만, 스터디원에 실력이 전반적으로 낮다면 우물안 개구리 스터디가 될수 있음.

스승님을 찾자. 내 코드를 피드백 해줄 수 있는 사람이면 좋다.

그것이 힘들면 오픈소스에 참가해보자. 보일러 프레이트 추천.

보일러 플레이트 : 실무에서 쓰일 만한 구조로 더 구체적으로 만들어둔 코드.

폴더 구조를 배우고, 실무에서 방향성을 제시해준다.

**개발시 데이터를 많이 넣어보기**

내가 예상하지못한 문제가 데이터가 많아지면 발생할 수 있음

**남의 코드를 많이 보자**

다른사람의 코드 피드백이나, 오픈 소스로 개발된 라이브러리 공부해보기.

자바 스크립트 코드 (D3, Jquery)를 공부하면 도움이 된다.

**에러 해결해보기**

에러는 오타가 대부분.

공식문서를 제대로 확인했는가

주변에 의존을 줄이자(최후의 수단)

기회가 되면 문제 해결 블로그를 만들어보자

**다양한 프레임워크를 익히기**

내가 아는 기존 프로임워크로 포팅해보기

포팅중 충돌이 났을때 해결보기

나만의 시그니쳐 프로젝트 만들기

**동시에 어떻게?**

자나깨나 공식문서를 참조하기

주기적으로 업데이트 데이 가지기

**결론**

-배워야할 이유를 찾자.

-적절한 공부 방법을 찾자.

-주기적으로 읽고 업데이트

앞으로 개발 생활에 도움이 되는 발표였던것같습니다.
